## 아이디어 A. 🚦 출근길 교통 브리핑 앱 (API 기반) — ✅ 근시일 후보(클라이언트 단독 가능)

**컨셉**: 집→회사 경로를 저장해두면, **아침 지정 시간대·N분 간격으로 예상 소요시간·정체·돌발상황을 정리해 음성 브리핑**. "언제 나가야 덜 막히는지"까지.

### 확보 가능한 교통 데이터 소스 (스크래핑 아님 = 공식 API)
| 소스 | 실시간/예측 | 비용 | 비고 |
|---|---|---|---|
| 카카오모빌리티 길찾기 | 실시간 + 미래운행(출발시각 예측) | **일 1만건 무료**, 초과 건당 8원 | 소요시간·통행료 반환. 개인용 사실상 무료 |
| TMAP API (SK) | 실시간 + 타임머신(시각 지정 예측) + 소통정보 | 무료 한도 有 | 자동차/대중교통 |
| 네이버클라우드 Directions 5/15 | 실시간 반영 | 유료(NCP) | 유류비·통행료까지 |
| ITS 국가교통정보센터 / 공공데이터포털 | 돌발상황(사고·공사·정체길이·우회) + 소통정보 | **무료** | 서울 TOPIS·경기 GITS 등 지자체 포함 |

### 아키텍처 (KDaily 모닝브리핑 재사용)
```
[경로 저장] → 아침 시간대·간격 (BriefingScheduler 재사용)
   → 라우팅 API 호출(실시간 ETA·정체) + ITS 돌발상황 보강
   → (선택)Gemini 자연어 요약 → TTS 낭독(TtsManager 재사용)
```
- **시간대별 비교**(카카오 미래운행/TMap 타임머신) = 킬러 기능("7시 vs 7시30분 출발").
- **재사용**: BriefingScheduler · TtsManager · 알림/포그라운드 · Gemini · DataStore · 다크골드 테마.
- **데이터 전략 권장**: 다 긁지 말고 → 경로/ETA는 **카카오 1개**(무료+예측) + 돌발상황 **ITS 무료** 조합.

### 보조 입력: 지역 교통 단톡방 활용 (⚠️ 방식별 리스크 큼)
| 방식 | Google Play | 카카오 약관 | 개인정보 | 판정 |
|---|---|---|---|:--:|
| 알림 읽기(NotificationListener) | restricted·고위험 | 위반 소지 | 타인 메시지 수집 | ❌ |
| 화면 읽기(Accessibility) | 2026 강화 — 접근성 목적 앱만, 제거 위험 | 위반 소지 | 타인 메시지 수집 | ❌ |
| 자동 화면 캡쳐(MediaProjection) | 타앱 캡쳐 민감 | 위반 소지 | 타인 메시지 수집 | ⚠️ 비권장 |
| **사용자 수동 캡쳐 → OCR** | 안전(사용자 행위) | 자기 화면 | 관리 필요 | ✅ **권장** |

- **결론**: "단톡방 자동 감시"는 3중 리스크(Play·카카오·PIPA)로 **불가**. 대신 **사용자가 스크린샷을 공유 → OCR로 위치·사건 추출 → 지오코딩해 지도 핀**은 안전·가능(KDaily OCR·Photo Picker·Gemini·지도 재사용).
- **개인정보 처리**: 온디바이스 OCR 우선(타인 메시지 클라우드 전송 회피), 교통정보만 최소 추출·원본 비저장, 면책 고지.

## 아이디어 B. 🗺️ 실시간 위치기반 교통 소셜앱 (Waze × 단톡방 × Zenly) — ⏸️ 기록만(중장기·헤비)

**컨셉**: 사용자 GPS로 지도 위에서 대화. 누가 말하면 **그 사람 위치에 말풍선**이 뜨고, **이동 방향**도 표시. 지역 실시간 교통 제보 커뮤니티.

> 🔴 **이 아이디어는 패밀리 최초로 서버·계정·실시간 통신이 필요** → 규모·비용·리스크가 기존 앱들과 급이 다름. "기록만" 상태.

### 기능 → 기술 매핑
| 기능 | 필요 기술 | 난이도 |
|---|---|:--:|
| 개인별 GPS 위치 | FusedLocationProvider(전경) | 중 |
| 단톡방처럼 대화 | 실시간 백엔드 + 사용자 계정/로그인 | 상 |
| 지도 연동 | 네이버/카카오 Map SDK(커스텀 마커) | 중 |
| 말한 사람 위치 표시 | 실시간 위치 공유(업로드→브로드캐스트) | 상 |
| 위치에 말풍선 | 마커 위 오버레이 + 실시간 갱신 | 중 |
| 이동 방향 | 연속 GPS로 방위각(bearing) 계산 → 마커 회전 | 중 |
| 앱 꺼져도 이동 표시 | ⚠️ 백그라운드 위치(Play 심사 관문) | 상+리스크 |
| 알림 | FCM 푸시 | 중 |

### 스택
- 지도: 네이버/카카오 Map SDK(Android)
- **실시간 백엔드(핵심)**: Firebase(Firestore/Realtime DB + Auth + FCM) 최단 경로 / 또는 자체 서버(Node+WebSocket) / Supabase·Ably
- 인증: Firebase Auth(전화·카카오·구글)
- 위치: FusedLocationProvider, 방위각 계산, (선택)백그라운드 위치
- 운영: 신고/차단/모더레이션, 개인정보 처리방침

### "확 무거워지는" 3대 이유
1. **첫 서버·계정 앱** → 월 서버/DB **비용 상시 발생**(KDaily는 0원), 운영·보안 부담.
2. **실시간 위치 공유 = 최고 민감**(스토킹·안전) → Play·PIPA 매우 엄격. 동의·방 권한·**위치 숨김/고스트 모드**·임시공유·미성년자 보호 필수.
3. **백그라운드 위치 = Play 심사 관문**(2026 정책: "핵심 기능 필수"만 승인, "있으면 좋은" 용도 거부). KDaily 권한 반려의 상위 난도판.

### 현실적 MVP (착수 시)
1. **전경(앱 열림)만 위치 공유** — 백그라운드 심사 회피
2. 지역/경로 단위 **방(room)** — 그 방 사람만 표시
3. 마커+말풍선+이동방향(bearing)+실시간 채팅
4. **임시 공유(방 나가면 위치 소멸)** + 위치 숨김 토글
5. 백엔드 = Firebase 서버리스로 시작(초기 무료 한도)

### KDaily 재사용도
- 제한적: 테마/다크골드·TTS·설정 저장 정도. 핵심(실시간 백엔드·지도·위치)은 전부 신규.

## 아이디어 C. 📻 라디오 / 워키토키 — 인터넷 라디오 ✅ 근시일 후보 / PTT ⏸️ 헤비

**말씀의 두 기능은 서로 다름**: (C-1) 여러 채널 라디오 듣기 / (C-2) 앱 사용자끼리 음성(PTT).

### C-1. 인터넷 라디오 (여러 채널 듣기) — ✅ 가능·쉬움
- 기술: 스트림 재생(ExoPlayer). **KDaily 오디오 플레이어·미니플레이어·MediaSession 재사용** → KDaily 오디오 탭 '라디오' 추가 또는 소형 신규 "K라디오".
- 데이터: **Radio Browser API**(무료·**키 불필요**·오픈소스, 전세계+한국 채널). 앱 비용 0원.
- ⚠️ 저작권: 한국 **전송권(공중송신)**상 방송사 허가 없는 재송신 불법. **지상파(KBS/MBC/SBS/TBS) 공식 스트림 무단 임베드 = 침해.** → 오픈 디렉터리의 **공개 스트림만**, 앱은 플레이어/디렉터리 역할. 지상파는 자체 앱 유도.
- ⚠️ "신호 안 잡힐 때" 현실: 인터넷 라디오는 **데이터 필요**. FM은 안 되나 셀룰러는 되는 곳=유효 / **완전 무신호 산속은 불가** → 보완책 = **미리 다운로드한 오디오 오프라인 재생**.

### C-2. 워키토키/PTT (앱 사용자끼리 음성) — ⏸️ 헤비·오프라인 불가
- Zello류도 **전부 인터넷(VoIP 릴레이)**. "무제한 거리"는 전파가 아니라 인터넷 덕분 → **앱만으로 "무신호 산속 통신" 불가.**
- 진짜 오프라인 근거리 = Bluetooth/WiFi Direct(**수십~100m**) 또는 LoRa 하드웨어뿐. 앱만으론 km 단위 무전 불가.
- 구현 시 WebRTC/음성 릴레이 서버 필요 → **아이디어 B와 같은 서버·계정·실시간 헤비군**(TURN·대역폭 비용).

### 정리
| 기능 | 가능 | 오프라인 | 서버 | 판정 |
|---|:--:|:--:|:--:|:--:|
| 인터넷 라디오 | ✅ | ❌(데이터 필요) | 불필요 | 근시일 후보 |
| 다운로드 오프라인 재생 | ✅ | ✅ | 불필요 | 라디오 보완책 |
| PTT/워키토키 | ⚠️ | ❌(인터넷 필요) | 필요(헤비) | 헤비군(B와 묶음) |
| 진짜 무전(무신호) | ❌ 앱만으론 | — | — | 하드웨어 영역 |

## 아이디어 E. 🚨 블랙박스 신고 도우미 — ⏸️ **검토 완료·착수 보류**(조건부 출시 가능)

**컨셉**: 블박 영상에서 위반 차량 증거(캡처 2~3장 + 번호판)를 정리해 **안전신문고 신고 문안까지** 만들어 주고, 제출·본인인증은 사용자가 직접.

> 📄 **상세 검토 = [SISTER_APP_DASHCAM_REPORT_PLAN.md](SISTER_APP_DASHCAM_REPORT_PLAN.md)** (2026-08-07). 규제 실측 검증·조건 7개·설계 스케치·미결사항 전부 그 문서에.

### 요지
- **원안(AI 위반 판별 + 클라우드 번호판 인식) = ❌**, **범위 축소본 = ✅ 조건부 출시 가능**.
- 🔑 **핵심 발견**: 안전신문고는 신고자의 법적 판단을 요구하지 않는다("위반 명칭은 담당 경찰관이 파악"). → **AI 위반 판별을 넣을 이유가 없고**, 넣으면 오판이 무고한 **제3자**에게 피해를 준다(면책 고지로 방어 안 됨). 조문 인용도 넣지 말 것.
- 🔑 **Gemini를 파이프라인에서 제거**하면 Google 생성형 AI 금지 사용 정책("동의 없는 개인정보·생체정보 이용", "동의 없는 추적·감시") 리스크가 사라진다. 번호판=**온디바이스 ML Kit**, 문안=**로컬 템플릿**. → **K-시리즈 최초로 Gemini를 안 쓰는 앱**.
- ⚠️ **불법주정차는 지원 불가** — 안전신문고 **앱 자체 카메라 사진만** 인정, 타 매체 촬영은 과태료 미부과. 앱이 도울 방법이 없어 안내만.
- ⚠️ 영상에 **시각 Burn-in 필수**(없으면 증거력 0). 블박 설정 문제라 앱이 못 만들어 줌.
- 📌 **권고 순서**: 앱보다 **개인 로컬 도구로 먼저 검증**. 최대 기술 리스크 = **야간·역광·모션블러에서 번호판 OCR이 실제로 읽히는가**. 여기서 안 읽히면 앱을 만들어도 못 쓴다.
