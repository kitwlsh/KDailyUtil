## 0. 한 줄

**관심종목에 새 공시가 뜨면 알려 주고, 그 공시가 «무슨 뜻인지»를 3줄로 풀어 준다.**

## 1. 왜 KDailyUtil에 넣나 · 무엇은 안 넣나

| | 판단 | 이유 |
|---|---|---|
| ✅ 관심종목 공시 알림 | **넣는다** | DART 호출(`StockRepository.fetchRecentDisclosures`)·`corpCode.xml` 캐시·Gemini·알림 채널이 **이미 있다**. 빠진 것은 «앱을 안 켜도 확인하는 일»(백그라운드)뿐 |
| ✅ 공시 갈래 분류 + AI 해설 | **넣는다** | 이미 있는 「📊 AI 실적 요약」을 **실적 외 공시**로 넓히는 것 |
| 🟡 내부자(임원·주요주주) 지분 변동 | **P3** | DART API가 «증감 수»는 주지만 **장내매수인지·금액**은 안 준다(§3-2) |
| ❌ 거래량 급증 · 이평선 돌파 · 외국인/기관 수급 | **안 넣는다** | 장중에 수시로 봐야 해서 **서버가 필요하다**. KDailyUtil은 서버 없는 앱이다 → Smart_stock 몫 |
| ❌ VIX·공포탐욕·환율·원자재 스프레드 | **안 넣는다** | 같은 이유 + 증시 탭의 목적(내 종목)과 거리가 있다 |
| ❌ «매수 신호» · «바닥 탈출» 같은 문구 | **절대 안 쓴다** | §8 정책. 이 앱은 **사실을 전한다** |

🔴 **차별점은 «알림»이 아니라 «해설»이다.** 공시 알림만이면 DART 앱·증권사 MTS·텔레그램 공시봇이 이미 무료로 한다.
우리가 더하는 것은 «이 `타법인주식및출자증권처분결정`이 회사에 무슨 의미인가»를 사람 말로 푸는 3줄이다.

## 3. 무엇을 감지하나

### 3-1. 공시 갈래 (P1 — 제목 키워드로 분류)

`list.json`의 `report_nm`(공시 제목)에 아래 키워드가 들어 있으면 그 갈래로 분류한다.
🔴 **갈래 이름에 «호재/악재»를 쓰지 않는다** — 같은 유상증자도 회사마다 뜻이 다르다. 판단은 해설이 하고, 그것도 «가능성»으로만 말한다.

| 갈래 | 배지 | 제목 키워드 (예) | 기본 |
|---|:--:|---|:--:|
| 희석·위험 | 🔴 | 유상증자결정 · 전환사채권발행결정 · 신주인수권부사채권발행결정 · 감자결정 · 관리종목 · 불성실공시 · 상장폐지 · 감사의견 · 조회공시요구 · 투자주의 | ON |
| 구조 변화 | 🔵 | 최대주주변경 · 타법인주식및출자증권처분 · 유형자산처분 · 영업양도 · 합병 · 분할 · 공개매수 | ON |
| 주주환원 | 🟢 | 자기주식취득결정 · 자기주식소각 · 현금ㆍ현물배당결정 | ON |
| 실적 | 🟡 | 영업(잠정)실적 · 매출액또는손익구조 · 분기보고서 · 반기보고서 · 사업보고서 | ON |
| 사업 | ⚪ | 단일판매ㆍ공급계약체결 · 신규시설투자 · 시설외투자 | OFF |
| 기타 | — | 위에 안 걸린 것 | 알림 없음, 목록에만 |

- **`[기재정정]`·`[첨부정정]`** 은 원 공시의 갈래를 따르되 기본 OFF(정정공시 토글).
- 🔴 **키워드 표는 코드에 박지 말고 `family.json` 또는 별도 원격 JSON으로 뺄지** 검토 → §10 결정 ④.
  DART 제목 표기(가운뎃점 `ㆍ` 등)가 바뀌어도 앱 재배포 없이 고칠 수 있다.
- 📌 **기존 `fetchRecentDisclosures`는 `pblntf_ty=A`(정기공시)만 받는다**(실적 요약용). 알림용 조회는 **`pblntf_ty` 없이** 따로 부른다 — 기존 함수를 바꾸면 「AI 실적 요약」 목록이 오염된다.

### 3-2. 내부자 지분 변동 (P3 — 확인 먼저)

- DART 지분공시 API `elestock.json`(임원ㆍ주요주주 소유보고)은 **보고자·직위·소유 주식 수·증감 수**를 준다.
- 🔴 **«장내매수인지 스톡옵션·상여인지»와 «금액»은 API 필드에 없다**(구현 전에 실제 호출로 확인할 것).
  Gemini 대화가 말한 «5,000만 원 이상 장내 매수»는 **원문(document.xml) 파싱이 필요하다** — P1·P2 범위 밖.
- P3 1안: **«증가했다»만 알린다** + 금액은 `증감 수 × 전일 종가(Yahoo)`로 **추정**이라고 밝힌다.
- P3 2안: 알림 탭 시 원문을 받아 Gemini가 «취득 사유»를 읽는다(키 있는 사용자만).

## 4. 동작 구조

```
WorkManager (PeriodicWork 또는 하루 4번 OneTime 체인)
  └─ DisclosureAlertWorker
       1. 관심종목(watchStockKeywordsFlow) → corp_code 변환 (corpCode.xml 캐시 · CORP_CODE_MAP)
          · 해외·코인·지수는 건너뛴다 (DART 대상 아님)
       2. 종목마다 list.json?corp_code=…&bgn_de=어제&end_de=오늘   (pblntf_ty 없음)
       3. rcept_no 로 «이미 본 공시» 걸러냄  ← seen 목록(최근 30일) 로컬 저장
       4. §3-1 갈래 분류 → 사용자가 켠 갈래만 남김
       5. 알림 (종목당 1건 · 같은 회차에 3건 넘으면 «롯데케미칼 외 2종목 · 공시 5건» 묶음)
       6. 알림 기록을 로컬에 저장 (증시 탭 «알림 기록»에서 다시 보기)
```

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 스케줄러 | **WorkManager** (의존성 신규 추가) | 정확한 시각이 필요 없다. 기존 브리핑은 `AlarmManager`(정시 필요)라 그대로 둔다 — 섞지 않는다 |
| 주기 | 하루 4번(08:30 · 12:30 · 16:30 · 19:30) · **주말·공휴일 쉼** | 공시는 장 마감 후(15:30~18:00)에 몰린다. 분 단위 감시는 앱의 일이 아니다 |
| 조건 | `NetworkType.CONNECTED` | 배터리·Doze는 WorkManager에 맡긴다. «몇 분 늦음»은 허용 |
| 첫 실행 | 켜는 순간 **알리지 않고 seen만 채운다** | 켜자마자 지난 공시 20건이 쏟아지는 것을 막는다 |
| 알림 채널 | `disclosure_alert_channel` 신설 | 기존 `ai_analysis_channel`과 분리 — 사용자가 하나만 끌 수 있게 |
| 탭 이동 | 기존 `NAVIGATE_TO=stock` + `STOCK_SUBTAB` + **`RCEPT_NO`** 추가 | `StockViewModel.notifyAnalysisDone`의 인텐트 형식을 그대로 따른다 |

## 5. AI 3줄 해설 (P2)

- **입력:** 공시 제목 + 회사명 + 갈래 + (가능하면) DART 주요사항보고서 API의 정형 필드. **원문 HTML 통째는 넣지 않는다**(FEATURE_DART_AI_SUMMARY §6 토큰 다이어트 원칙)
- **출력 형식(고정):**

```
무슨 일: (공시 내용을 숫자와 함께 한 줄)
무슨 뜻: (회사에 일반적으로 어떤 의미일 수 있는지 한 줄 — «~일 수 있다»)
확인할 점: (투자자가 다음에 확인해 볼 것 한 줄)
```

- **프롬프트 금지 조항(시스템 프롬프트에 못 박는다):**
  - 매수·매도·보유 권유, 목표가, «오를 것/내릴 것» 예측 금지
  - 입력에 없는 숫자를 만들지 말 것. 숫자가 없으면 «공시 원문 확인 필요»
  - 호재/악재 단정 금지 — «희석 가능성», «현금 확보 목적일 수 있음» 같은 가능성 표현만
- **캐시:** `rcept_no` 키로 로컬 저장. 같은 공시는 다시 부르지 않는다(§14-2 원칙)
- **신고:** 「📊 AI 실적 요약」에 붙인 🚩 신고(`AiContentReport`)를 **그대로 재사용** — Play 「AI 생성 콘텐츠」 정책

## 7. DART 호출량 · 공용 키 문제

- 1회 조회 = 관심 국내 종목 수만큼 `list.json` 호출. **10종목 × 하루 4번 = 사용자당 하루 40회**.
- 공용 키(`BuildConfig.DART_DEFAULT_KEY`)는 **모든 설치가 함께 쓴다.** FEATURE_DART_AI_SUMMARY §2·§13은 한도를 «일 10,000회»로 적었다
  → 단순 계산으로 **약 250명이 켜면 공용 키가 바닥난다** (🔴 실제 한도는 DART 공지로 다시 확인할 것).
- 대책 후보 → §10 결정 ②
  - A. 백그라운드 알림은 **개인 DART 키가 있을 때만** 켠다 (안전, 문턱 높음)
  - B. 공용 키로 허용하되 **관심종목 10개 · 하루 4번** 상한 + 429/한도 오류 시 그날은 조용히 쉰다
  - C. 공용 키 사용자는 하루 2번(12:30 · 19:30)으로 줄인다
- 🟢 **추천: B + 한도 오류 시 «개인 키를 넣으면 계속 받을 수 있어요» 안내.** 지금 설치 규모에서는 B로 충분하고, 문제가 생기면 C로 내린다.

## 8. 정책 · 문구

- 🔴 **이 기능은 «정보 전달»이다.** 알림 제목·본문·해설 어디에도 «매수/매도/신호/추천/바닥/급등 예상»을 쓰지 않는다.
  유사투자자문업(불특정 다수에게 투자 판단을 조언)이나 Play 금융 정책과 엮일 표현을 처음부터 피한다.
- 면책 문구: 기존 [STORE_LISTING.md](STORE_LISTING.md) 54행 문구를 카드 하단에 한 줄로.
- 🔴 [PLAY_POLICY_COMPLIANCE.md](PLAY_POLICY_COMPLIANCE.md) 101행은 «금융 데이터를 다루지 않는다»고 적었다.
  공시는 공개 데이터라 «사용자 금융 정보»는 아니지만, **출시 전에 그 문단을 다시 읽고 고칠지 판단**한다.
- 개인정보처리방침: 새로 모으는 정보 없음(관심종목은 이미 기기 안에 있다). 외부 전송 = DART·Gemini(기존과 같음).
- 데이터 보안 칸: 변경 없음 예상 — **출시 때 확인**.
