## 3. ⭐ 데이터 보안(Data Safety) 양식 — 방침과 반드시 일치시킨다

### 3-1. 무엇이 문제였나 (KDailyUtil 실제 사례)

**개인정보처리방침(웹페이지)과 데이터 보안 양식(Console)은 별개로 관리되는데, 둘이 어긋나면 정책 위반이다.**

2026-08-10에 KDailyUtil 방침 제8조에 *"무료 등급에서는 Google이 제품 개선에 사용할 수 있고 사람이 검토할 수 있다"* 를 추가했다. 그런데 데이터 보안 양식은 **2026-06-25(v1.1 시점)에 멈춰 있었고**, 스토어 미리보기에 이렇게 떠 있었다:

> 🛡 **제3자와 공유되는 데이터 없음** — 개발자에 따르면 앱에서 사용자 데이터를 타사 또는 타 기관과 공유하지 않습니다.

**같은 사실을 두고 방침은 "Google이 제품 개선에 쓴다", 스토어는 "공유 안 함"** 이라고 말하는 모순 상태였다.

원인은 **`수집됨`만 체크되고 `공유됨`이 비어 있던 것**이다.

### 3-2. 판단 기준 — AI로 데이터를 보내는 앱은 이렇게

양식 자체의 정의: *"'공유됨'이란 데이터가 사용자 기기 내부 또는 외부에 있는 **타사로 전송**된다는 의미"*.
**Gemini API = 개발자 입장에서 타사(Google LLC)** 이므로 전송은 곧 공유다.

| 항목 | 답 | 이유 |
|---|---|---|
| 수집됨 | ✅ | 기기 밖으로 나감 |
| **공유됨** | ✅ | **타사(Google)로 전송** |
| **임시 처리** | ❌ **아니요** | 임시 처리 = *메모리에 있는 동안만, 실시간 처리에 필요한 시간만 보관*. **무료 등급은 제품 개선에 쓰고 사람이 검토**하므로 해당 없음 |
| 필수/선택 | **선택** | AI 기능을 실행할 때만 전송, 안 쓰면 앱은 정상 동작 |
| 수집 목적 / **공유 목적** | **앱 기능**만 | 애널리틱스·광고·맞춤설정·계정관리 전부 아님 |

> 💡 **`공유됨`을 켜면 "왜 공유하나?"가 새로 나타난다.** 수집 목적과 별개 질문이며, 답은 똑같이 **`앱 기능`** 하나다.
> 💡 *"Google이 무료 등급 데이터를 자기 제품 개선에 쓴다"* 를 적을 칸은 **목적 목록에 없다.** 그 질문은 "개발자인 당신이 왜 넘기나"를 묻는 것이고, Google의 후속 이용은 **방침에 서술**하고 양식에서는 **`공유됨` 체크 자체가 신고 역할**을 한다.

**⚠️ 알아둘 애매함**: 양식에는 `예외 보기` 링크가 있고 *"사용자가 직접 시작한 작업으로 전송되는 경우"* 예외가 통상 포함된다. 이를 근거로 미체크를 유지하는 해석도 가능하다. **그럼에도 체크를 권하는 이유**는 ① 또 다른 예외인 "대행 처리 업체"는 *그 업체가 개발자를 위해서만 처리할 때* 적용되는데 **무료 등급은 Google 자신의 제품 개선에도 쓰므로 벗어나고**, ② 방침에 이미 그렇게 적어 배포했으므로 **미체크는 모순**이기 때문이다.

### 3-3. KDailyUtil 확정 상태 (2026-08-11)

**데이터 유형 2가지** — 앱 실태와 일치함을 확인했다.

| 유형 | 근거 |
|---|---|
| **사진 및 동영상 > 사진** | 카메라 촬영·선택 이미지가 OCR·퀴즈 생성 위해 Gemini로 전송 |
| **앱 활동 > 기타 사용자 제작 콘텐츠** | AI 질문·붙여넣은 글이 Gemini로 전송 |

**미체크가 맞는 것** — 의존성을 실제로 확인한 결과다.

| 유형 | 근거 |
|---|---|
| 앱 정보 및 성능(비정상 종료 로그 등) | **Crashlytics·Analytics·Sentry 등 수집 SDK가 하나도 없다** |
| 기기 또는 기타 ID | 광고 SDK 없음, 광고 ID 미사용 |
| 오디오 파일 | 녹음은 **기기 안에만** 저장, 외부 전송 없음 |
| 파일 및 문서 | 이미지는 '사진'으로 커버, `.kquiz`는 로컬 |
| 위치·개인정보·금융·건강·메시지·연락처·Calendar·웹탐색 | 앱이 다루지 않음 |

> **사용자 데이터를 기기 밖으로 보내는 라이브러리는 `generative.ai`(Gemini) 하나뿐**이다. 나머지(Compose·jsoup·DataStore·Coil·WorkManager)는 사용자 데이터를 외부로 보내지 않는다. → 신규 의존성을 추가할 때 이 전제가 깨지는지 확인할 것.

**음성 입력(STT) 판단**: `오디오 파일` 미체크를 유지한다. 안드로이드 표준 `SpeechRecognizer`는 **OS가 제공하는 시스템 기능**이지 앱이 번들한 SDK가 아니고, 앱이 오디오를 직접 서버로 보내지 않는다. 방침 제1조에 *"기기 설정에 따라 해당 서비스로 음성이 전달되어 처리될 수 있다"* 고 **이미 투명하게 서술**해 두어 모순이 아니다.

### 3-4. K장부 — ✅ **점검 완료(2026-08-11, K장부 세션): 어긋나 있어 고쳤다**

> 이 절은 원래 "K장부 세션이 점검할 것" 목록이었다. **그 세션이 같은 날 점검을 끝냈고, 예상대로 신고 범위가 더 넓었다.**
> KLotto645분도 08-11에 끝났다 → §3-5(조치 불필요).

**그 세션이 Console에 최종 입력한 것** (미리보기 스크린샷으로 검증, 근거·클릭 절차 = `KJangbu/doc/STORE_SUBMISSION.md` §4-2~4-5):

| 데이터 유형 | 수집됨 | 공유됨 | 임시 처리 | 필수/선택 | 목적 |
|---|---|---|---|---|---|
| 금융 정보 > **구매 내역** | ✅ | ✅ | ❌ | 선택 | 앱 기능 |
| 금융 정보 > **기타 금융 정보** | ✅ | ✅ | ❌ | 선택 | 앱 기능 |
| **메시지 > SMS/MMS** · 사진 및 동영상 · 앱 활동 | ✅ | ✅ | ❌ | 선택 | 앱 기능 |

→ 스토어 미리보기에 *"데이터가 제3자와 공유됨: 금융 정보, 메시지, 사진 및 동영상, 앱 활동"* 이 뜨는 것까지 확인했다. **KDailyUtil보다 신고 범위가 2단계 넓다**(금융 정보 2종 + SMS 추가). **v1.0.1(vc2)과 함께 2026-08-11 라이브** — 양식을 넓게 고쳐도 심사가 지연되지 않았다(당일 통과).

**아래는 점검 전에 KDailyUtil 세션이 `KJangbu` 코드를 읽기만 해서 정리한 예상 항목이다** — 결과적으로 세 건 모두 실제 신고로 이어졌으므로, 다음 신규 앱을 점검할 때 같은 순서로 보면 된다.

**① 사진 외에 '텍스트'도 Gemini로 간다**

```
AndroidManifest.xml      공유 시트 수신: 영수증 이미지/문자 던지기 (ACTION_SEND)
MainActivity.kt          intent.getStringExtra(Intent.EXTRA_TEXT)
ReceiptReviewScreen.kt   gemini.extractReceiptsFromText(sharedText)
GeminiManager.kt         "다음은 결제 문자/알림 또는 이용내역 텍스트야…"
```

사용자가 **결제 문자를 공유하면 그 본문이 Google로 전송**된다. → `메시지 > SMS 또는 MMS` 또는 `앱 활동 > 기타 사용자 제작 콘텐츠` 검토 필요.

**② 보내는 내용이 '금융 정보'다**

`extractReceipts`(영수증) · `extractRecurring`(정기결제) · `extractAccountTxs`(**계좌 거래내역**) · `extractSecuritiesTxs`(**증권 거래내역**) · `extractCarRecords`.

데이터 보안에는 **`금융 정보`** 카테고리(사용자 결제 정보 / **구매 내역** / 신용 점수 / 기타)가 따로 있다. **거래·구매 내역을 타사로 보낸다면 사진과 별개로 신고 대상일 수 있다.**

**③ 방침에 무료 등급 고지가 있는지** — KDailyUtil 제8조와 같은 문구가 K장부 방침에도 필요한지 확인. **K장부는 AI 키 체험(개발자 키) 기능이 있어 체험 사용자의 데이터가 개발자 키로 전송**된다는 점도 함께 고려할 것.

> ⚠️ **위험도가 다르다.** KDailyUtil이 보내는 건 뉴스·책 페이지지만, **K장부가 보내는 건 계좌·카드·증권 거래내역**이다. *"무료 등급에서 Google이 제품 개선에 쓰고 사람이 검토할 수 있다"* 가 훨씬 민감하게 작용한다.

### 3-5. KLotto645 — ✅ **점검 종료(2026-08-11): 조치할 것이 없었다**

세 앱 중 유일하게 **사용자 데이터가 기기 밖으로 나가지 않는다.** 그리고 **방침 · 코드 · Console 세 곳이 이미 일치**한다 — §4-1의 "세 곳이 한 세트" 규칙을 충족한 유일한 앱이다.

**Console 실제 값 확인(2026-08-11, KLotto 세션):** `앱 콘텐츠 > 데이터 보안 > 2 데이터 수집 및 보안`의
*"앱에서 필수 사용자 데이터 유형을 수집하거나 공유하나요?"* = **아니요**.
→ 우려했던 **`사진` 과잉 신고는 없었다.** '아니요'라서 `3 데이터 유형` 단계로 내려가지 않아 사진 체크박스가 생기지도 않는다. 광고 ID도 해당 없음(SDK 0개).

저장소를 읽어 확인한 근거:

| 확인 항목 | 결과 |
|---|---|
| **AI 전송** | ❌ **없음.** `GenerativeModel`·`generateContent`·`generativeai` 가 **0건**. 'AI 추천'은 `util/LottoAIScorer.kt`의 **기기 내부 계산**이고 이름만 AI다. 문서에 보이는 Gemini/ChatGPT 언급은 전부 **외부 UX 검토 기록**이라 런타임과 무관 |
| **사진이 생성조차 되지 않음** ⭐ | `ScanQrActivity.kt`는 **`ImageAnalysis`만** 바인딩한다(`STRATEGY_KEEP_ONLY_LATEST`). `ImageCapture`·`takePicture`·`MediaStore`·`FileOutputStream` **전부 0건** — 프레임은 `QrCodeAnalyzer`가 메모리에서 해독한 뒤 `image.close()`로 버린다. 즉 사진은 *기기 밖으로 나가지 않는 것이 아니라 **파일로 존재하지 않는다*** |
| **사진 접근 권한 없음** ⭐ | 매니페스트 권한은 `INTERNET`·`ACCESS_NETWORK_STATE`·`POST_NOTIFICATIONS`·`CAMERA` **4개뿐**. `READ_MEDIA_IMAGES`·`READ_EXTERNAL_STORAGE` 전무 |
| **QR 해독** | ✅ **완전 온디바이스.** CameraX 프레임 → **zxing(`com.google.zxing:core`) 로컬 해독** → `util/LottoQrParser.kt`가 **URL을 열지 않고 `v=` 파라미터만 파싱**한다(정규식 3개로 문자열만 자르는 **순수 함수**). `ScanQrActivity.kt`에 `ACTION_VIEW`·`startActivity`·`Uri.parse` **0건** — 용지 QR의 `m.dhlottery.co.kr` 주소를 **호출하지 않는다** |
| **수집 SDK** | ❌ **없음.** Crashlytics·Firebase·Analytics·AdMob 전무. 의존성은 zxing·CameraX·Room(로컬 DB)·jsoup·WorkManager·recyclerview·coroutines·splashscreen·material뿐 |
| **업로드 경로** | ❌ **없음.** `POST` 검색 결과는 전부 `POST_NOTIFICATIONS` 권한 또는 `View.post()`. `OutputStream`은 `RemoteIconCache`의 **다운로드 버퍼**(`ByteArrayOutputStream`) |
| **네트워크 목적지 전수** | ⬇️ **내려받기 전용.** 동행복권 2경로 + 네이버 검색 + `raw.githubusercontent.com`(family.json) + 화이트리스트 아이콘 URL. **쿼리에 실리는 값은 회차 번호뿐**(`drwNo=$round`, `query=${round}회로또당첨번호`) → 사용자가 산 번호가 URL에 들어가는 경로가 없다 |

→ **사용자가 산 번호는 기기 안에서만 처리되고, 당첨 확인은 공개 당첨번호를 내려받아 기기에서 대조한다.**

**방침 서술 검토 결과** — 카메라·QR 서술(제1조)은 실제 동작과 **이미 정확히 일치**했다(*"실시간으로만 사용되며 사진·영상을 저장하거나 외부로 전송하지 않습니다"*). 제8조의 *"생성형 AI 서비스를 이용하지 않으므로…"* 도 코드와 일치 — **세 앱 중 이 문장을 쓸 수 있는 건 KLotto뿐**이다. 정확성 차원의 보정 2건만 반영했다(최종 개정일자 8/3 → 8/11):

- **`allowBackup`** — `android:allowBackup="true"`(Android 기본값)라 *"앱 삭제 시 즉시 완전 소멸"* 과 미세하게 어긋났다 → 제2·3조에 **OS 자동 백업(Android Backup)** 경로를 명시. 🚫 **코드를 `false`로 바꾸지 않았다** — 이 앱의 핵심 가치가 '내 번호 이력'이라 기기 교체 시 그것이 사라진다. **이 항목은 데이터 보안 양식의 '수집'이 아니다**(OS 기능이고 개발자가 접근 불가) → §2의 '아니요'는 그대로 유효.
- **쿠키** — 원문이 *"활동을 **추적하는** 광고 식별자 트래커나 쿠키"* 여서 dhlottery `JSESSIONID`(리다이렉트 회피용 세션 쿠키, 메모리에만 유지)는 **애초에 걸리지 않았다.** 우려가 과했던 항목이며 "전혀"의 오독 여지만 제6조에 명시로 해소.

> 🚫 **KLotto에 `ImageCapture`를 도입하지 말 것.** QR 해독에 필요하지 않은데, 도입하면 사진 파일이 실제로 생기면서 위 ⭐근거 두 개가 동시에 무너지고 데이터 보안 양식 재검토가 필요해진다.

## 4. 🔁 재발 방지 규칙

1. **방침을 고치면 데이터 보안 양식도 같이 본다.** 이번에 실제로 어긋났다. 방침(웹) → 배포본(`k-series-config`) → **Console 양식** 세 곳이 한 세트다.
2. **권한·의존성을 추가하면 세 곳을 함께 갱신한다** — 매니페스트 / 방침 / 데이터 보안 양식.
3. **데이터 보안 양식의 '최종 수정 날짜'를 릴리스마다 본다.** KDailyUtil은 v1.1(2026-06-25) 이후 **네 번의 릴리스 동안 방치**돼 있었다. 날짜가 오래됐으면 그 사이 추가된 데이터 흐름이 빠졌다는 신호다.
4. **양식은 앱 배포와 무관하게 즉시 고칠 수 있다.** 새 버전을 기다릴 필요 없다.
