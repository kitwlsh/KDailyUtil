> **작성 2026-08-11.** KDailyUtil v1.6.1 업로드 과정에서 Play Console을 실제로 훑어보며 확인한 것들.
> **이 문서는 3개 앱(KDailyUtil·KLotto645·K장부) 공통 기준이다.** K장부·KLotto645 세션은 §3을 읽고 자기 앱을 점검할 것.

## 1. Android 개발자 인증 — ✅ 확인 완료, 할 일 없음

**2026년 9월 30일까지 모든 Google Play 앱이 '등록'되어야 하고, 미등록 앱은 전 세계 Play에서 삭제된다.** (2026-08월 Google 메일 공지)

**확인 결과(2026-08-11): 패키지 이름 7개 전부 `등록됨`.** 조치 불필요.

| 패키지 | 상태 |
|---|---|
| `com.kitwlshcom.kdailyutil` · `com.kitwlshCom.klotto645` · `com.kitwlshcom.kjangbu` | ✅ 등록됨 |
| `com.kitwlshcom.Random6Num`(Create6Num) · `com.KitwlshCom`(KitwLappy2) · `com.KitwlshCom.KitwlshLappy`(KitwTest) · `com.kitwlshcom.kitwlshlappy2` | ✅ 등록됨 |

**왜 자동으로 됐나**: 세 앱 모두 **Play 앱 서명**에 등록돼 있어서다. Google 공지가 말한 *"99% 이상이 Google Play 서명 키를 사용하여 자동 등록"* 에 해당한다.

**해당 없는 항목**: 공지의 "Play 외부 배포 앱 등록", "외부 서명용 추가 키 추가" 두 가지는 **우리와 무관**하다 — 세 앱 모두 Play로만 배포한다.

> 확인 위치: Play Console 왼쪽 메뉴 최하단 **`Android 개발자 인증`** > `패키지 이름` 탭

**방치해도 되는 근거**:
- 개발자 인증 기한 → 7개 전부 등록되어 리스크 없음
- 출시 안 된 앱은 사용자에게 노출되지 않음
- "아직 검토를 위해 전송되지 않음" = 저장만 하고 제출 안 한 변경사항. 무해

> ⚠️ 단, `KitwLappy2`·`kitwlshLappy2`의 **"Google에서 삭제"는 보통 정책 위반**으로 내려간 것이다. 이미 지난 일이나 **위반 이력이 쌓이면 계정 제재** 대상이 될 수 있다. `정책 상태` 메뉴에 **미해결 경고가 남아 있는지** 가끔 확인할 것.

## 3. ⭐ 데이터 보안(Data Safety) 양식 — 방침과 반드시 일치시킨다

### 3-1. 무엇이 문제였나 (KDailyUtil 실제 사례)

**개인정보처리방침(웹페이지)과 데이터 보안 양식(Console)은 별개로 관리되는데, 둘이 어긋나면 정책 위반이다.**

2026-08-10에 KDailyUtil 방침 제8조에 *"무료 등급에서는 Google이 제품 개선에 사용할 수 있고 사람이 검토할 수 있다"* 를 추가했다. 그런데 데이터 보안 양식은 **2026-06-25(v1.1 시점)에 멈춰 있었고**, 스토어 미리보기에 이렇게 떠 있었다:

> 🛡 **제3자와 공유되는 데이터 없음** — 개발자에 따르면 앱에서 사용자 데이터를 타사 또는 타 기관과 공유하지 않습니다.

**같은 사실을 두고 방침은 "Google이 제품 개선에 쓴다", 스토어는 "공유 안 함"** 이라고 말하는 모순 상태였다.

원인은 **`수집됨`만 체크되고 `공유됨`이 비어 있던 것**이다.

### 3-2. 판단 기준 — AI로 데이터를 보내는 앱은 이렇게

양식 자체의 정의: *"'공유됨'이란 데이터가 사용자 기기 내부 또는 외부에 있는 **타사로 전송**된다는 의미"*.
**Gemini API = 개발자 입장에서 타사(Google LLC)** 이므로 전송은 곧 공유다.

| 항목 | 답 | 이유 |
|---|---|---|
| 수집됨 | ✅ | 기기 밖으로 나감 |
| **공유됨** | ✅ | **타사(Google)로 전송** |
| **임시 처리** | ❌ **아니요** | 임시 처리 = *메모리에 있는 동안만, 실시간 처리에 필요한 시간만 보관*. **무료 등급은 제품 개선에 쓰고 사람이 검토**하므로 해당 없음 |
| 필수/선택 | **선택** | AI 기능을 실행할 때만 전송, 안 쓰면 앱은 정상 동작 |
| 수집 목적 / **공유 목적** | **앱 기능**만 | 애널리틱스·광고·맞춤설정·계정관리 전부 아님 |

> 💡 **`공유됨`을 켜면 "왜 공유하나?"가 새로 나타난다.** 수집 목적과 별개 질문이며, 답은 똑같이 **`앱 기능`** 하나다.
> 💡 *"Google이 무료 등급 데이터를 자기 제품 개선에 쓴다"* 를 적을 칸은 **목적 목록에 없다.** 그 질문은 "개발자인 당신이 왜 넘기나"를 묻는 것이고, Google의 후속 이용은 **방침에 서술**하고 양식에서는 **`공유됨` 체크 자체가 신고 역할**을 한다.

**⚠️ 알아둘 애매함**: 양식에는 `예외 보기` 링크가 있고 *"사용자가 직접 시작한 작업으로 전송되는 경우"* 예외가 통상 포함된다. 이를 근거로 미체크를 유지하는 해석도 가능하다. **그럼에도 체크를 권하는 이유**는 ① 또 다른 예외인 "대행 처리 업체"는 *그 업체가 개발자를 위해서만 처리할 때* 적용되는데 **무료 등급은 Google 자신의 제품 개선에도 쓰므로 벗어나고**, ② 방침에 이미 그렇게 적어 배포했으므로 **미체크는 모순**이기 때문이다.

### 3-3. KDailyUtil 확정 상태 (2026-08-11)

**데이터 유형 2가지** — 앱 실태와 일치함을 확인했다.

| 유형 | 근거 |
|---|---|
| **사진 및 동영상 > 사진** | 카메라 촬영·선택 이미지가 OCR·퀴즈 생성 위해 Gemini로 전송 |
| **앱 활동 > 기타 사용자 제작 콘텐츠** | AI 질문·붙여넣은 글이 Gemini로 전송 |

**미체크가 맞는 것** — 의존성을 실제로 확인한 결과다.

| 유형 | 근거 |
|---|---|
| 앱 정보 및 성능(비정상 종료 로그 등) | **Crashlytics·Analytics·Sentry 등 수집 SDK가 하나도 없다** |
| 기기 또는 기타 ID | 광고 SDK 없음, 광고 ID 미사용 |
| 오디오 파일 | 녹음은 **기기 안에만** 저장, 외부 전송 없음 |
| 파일 및 문서 | 이미지는 '사진'으로 커버, `.kquiz`는 로컬 |
| 위치·개인정보·금융·건강·메시지·연락처·Calendar·웹탐색 | 앱이 다루지 않음 |

> **사용자 데이터를 기기 밖으로 보내는 라이브러리는 `generative.ai`(Gemini) 하나뿐**이다. 나머지(Compose·jsoup·DataStore·Coil·WorkManager)는 사용자 데이터를 외부로 보내지 않는다. → 신규 의존성을 추가할 때 이 전제가 깨지는지 확인할 것.

**음성 입력(STT) 판단**: `오디오 파일` 미체크를 유지한다. 안드로이드 표준 `SpeechRecognizer`는 **OS가 제공하는 시스템 기능**이지 앱이 번들한 SDK가 아니고, 앱이 오디오를 직접 서버로 보내지 않는다. 방침 제1조에 *"기기 설정에 따라 해당 서비스로 음성이 전달되어 처리될 수 있다"* 고 **이미 투명하게 서술**해 두어 모순이 아니다.

### 3-4. 🔴 K장부·KLotto645 세션이 점검할 것

**K장부는 KDailyUtil보다 신고 범위가 넓을 가능성이 높다.** (아래는 `KJangbu` 코드를 **읽기만** 해서 확인한 것이며, 최종 판단은 그 세션 몫이다.)

**① 사진 외에 '텍스트'도 Gemini로 간다**

```
AndroidManifest.xml      공유 시트 수신: 영수증 이미지/문자 던지기 (ACTION_SEND)
MainActivity.kt          intent.getStringExtra(Intent.EXTRA_TEXT)
ReceiptReviewScreen.kt   gemini.extractReceiptsFromText(sharedText)
GeminiManager.kt         "다음은 결제 문자/알림 또는 이용내역 텍스트야…"
```

사용자가 **결제 문자를 공유하면 그 본문이 Google로 전송**된다. → `메시지 > SMS 또는 MMS` 또는 `앱 활동 > 기타 사용자 제작 콘텐츠` 검토 필요.

**② 보내는 내용이 '금융 정보'다**

`extractReceipts`(영수증) · `extractRecurring`(정기결제) · `extractAccountTxs`(**계좌 거래내역**) · `extractSecuritiesTxs`(**증권 거래내역**) · `extractCarRecords`.

데이터 보안에는 **`금융 정보`** 카테고리(사용자 결제 정보 / **구매 내역** / 신용 점수 / 기타)가 따로 있다. **거래·구매 내역을 타사로 보낸다면 사진과 별개로 신고 대상일 수 있다.**

**③ 방침에 무료 등급 고지가 있는지** — KDailyUtil 제8조와 같은 문구가 K장부 방침에도 필요한지 확인. **K장부는 AI 키 체험(개발자 키) 기능이 있어 체험 사용자의 데이터가 개발자 키로 전송**된다는 점도 함께 고려할 것.

> ⚠️ **위험도가 다르다.** KDailyUtil이 보내는 건 뉴스·책 페이지지만, **K장부가 보내는 건 계좌·카드·증권 거래내역**이다. *"무료 등급에서 Google이 제품 개선에 쓰고 사람이 검토할 수 있다"* 가 훨씬 민감하게 작용한다.

**KLotto645**: AI로 사용자 데이터를 전송하는 경로가 없다면 해당 없음. 있는지만 확인.

## 4. 🔁 재발 방지 규칙

1. **방침을 고치면 데이터 보안 양식도 같이 본다.** 이번에 실제로 어긋났다. 방침(웹) → 배포본(`k-series-config`) → **Console 양식** 세 곳이 한 세트다.
2. **권한·의존성을 추가하면 세 곳을 함께 갱신한다** — 매니페스트 / 방침 / 데이터 보안 양식.
3. **데이터 보안 양식의 '최종 수정 날짜'를 릴리스마다 본다.** KDailyUtil은 v1.1(2026-06-25) 이후 **네 번의 릴리스 동안 방치**돼 있었다. 날짜가 오래됐으면 그 사이 추가된 데이터 흐름이 빠졌다는 신호다.
4. **양식은 앱 배포와 무관하게 즉시 고칠 수 있다.** 새 버전을 기다릴 필요 없다.
