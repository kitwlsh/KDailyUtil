## 1. 컨셉

**블랙박스 영상에서 위반 차량 증거를 정리해, 안전신문고에 붙여넣을 수 있는 신고 문안까지 만들어 주는 앱.** 제출·본인인증은 사용자가 안전신문고 앱/웹에서 직접 한다.

검토의 출발점은 사용자가 Gemini 3.1 Pro와 상담한 내용(2026-08-07)이었고, 그 상담은 "상용 앱은 규제로 불가, 개인용 로컬 스크립트가 현실적"으로 결론냈다. **이 문서는 그 결론을 일부 수정한다** — 범위를 좁히면 출시가 가능하다.

---

## 2. 범위 — 원안 vs 확정

**결정적 차이는 '앱이 판단하는가'다.**

| 단계 | 원안 (Gemini 상담) | ✅ 확정 범위 |
|---|---|---|
| 영상 → 프레임 추출 | FFmpeg/OpenCV 자동 | 사용자가 구간 선택 + 프레임 추출 |
| **위반 판별** | **AI가 신호위반·중앙선침범 등 자동 판별** | ❌ **하지 않음** — 사용자가 유형 선택(§4) |
| 번호판 인식 | **Claude Vision / Gemini API**(클라우드) | **온디바이스 OCR만**(ML Kit) |
| 신고 문안 | AI 생성 + 도로교통법 조문 인용 | **로컬 템플릿** 조립, **조문 인용 없음**(§4) |
| 제출 | Playwright 브라우저 자동화 | ❌ 하지 않음 — 사용자가 안전신문고에서 직접 |

원안을 그대로 만들면 막히지만, **확정 범위는 기능 손실이 거의 없다.** 이유는 §4.

## 4. 🔑 핵심 발견 — 위반 판별은 앱이 할 일이 아니다

안전신문고 신고 작성 안내에 명시돼 있다:

> *"신고대상 차량이 위반했다고 생각하시는 사항을 **정황과 함께 기재**하면, 담당 경찰관님께서 **적절한 위반 명칭을 찾아서 파악**해주시니 **너무 법에 맞추어 기재할 필요는 없습니다.**"*

**제도 자체가 신고자의 법적 판단을 요구하지 않는다.** 위반 유형 확정은 경찰관 몫이다. 이 사실이 설계를 두 군데 바꾼다.

1. **AI 위반 판별을 넣을 이유가 없다.** 넣으면 오판 리스크만 생기고 제도상 이득이 없다. → 최대 우려였던 "AI가 위반이라 했는데 아니어서 무고한 제3자가 피해" 가 **설계 차원에서 소멸**한다. (이 리스크는 K-시리즈의 투자·의료 면책과 성격이 다르다. 피해자가 앱 사용자가 아니라 **제3자**여서 면책 고지로 방어되지 않는다.)
2. **조문 인용은 넣지 말아야 한다.** 원안 예시 문안의 `도로교통법 제5조` 같은 인용은 잘못 짚으면 허위 주장처럼 보이고, 경찰이 알아서 분류하니 이득도 없다.

→ 앱이 할 일은 **사실 정리**뿐이다: 일시 · 장소 · 차량번호 · 정황 서술 · 증거 캡처.

### 두 벽이 사라지는 방식

| 리스크 | 확정 범위에서는 |
|---|---|
| 🔴 AI 오판 → 제3자 피해 | **소멸** — 앱이 판별하지 않고, 제도도 요구하지 않는다 |
| 🔴 Google 생성형 AI 약관 | **회피** — 번호판은 온디바이스 ML Kit, 문안은 로컬 템플릿. **Gemini를 파이프라인에서 완전히 제거**하면 이 약관이 적용될 일이 없다. 문자열 조립에 AI는 애초에 불필요 |

> 💡 즉 이 앱은 **K-시리즈 최초로 Gemini를 쓰지 않는 앱**이 된다. 그게 리스크 회피의 핵심이다.

## 5. 출시 조건 7개 (전부 충족 가능)

1. **앱이 위반을 단정하지 않는다** — 유형은 사용자가 목록에서 선택(안전신문고 분류 그대로: 교통위반·이륜차 위반·버스전용차로 위반·번호판 규정 위반·불법 튜닝·적재물 추락방지 등). 앱은 정황 서술을 **도울** 뿐. **조문 인용 금지**
2. **번호판 인식 = 온디바이스만** — ML Kit Text Recognition(한국어). 클라우드·서버 전송 없음
3. **완전 로컬·무보관** — 영상·번호판을 서버로 보내지 않고, 신고 완료 후 **삭제 유도**. K-시리즈 공통 원칙과 동일
4. **불법주정차는 기능에서 제외** — 안전신문고 앱 자체 카메라 사진만 인정되므로 도울 수 없다. 대신 앱 안에서 **"불법주정차는 안전신문고 앱으로 직접 촬영해야 합니다"** 라고 안내해 사용자가 헛수고하지 않게
5. **시각 Burn-in 사전 안내** — 영상에 날짜·시:분:초가 없으면 증거력이 없다. 블박 설정 문제라 앱이 만들어 줄 수 없으므로 첫 화면에서 확인시킨다
6. **방침에 명시** — 타인 영상·번호판을 기기 내에서만 처리, 전송·보관 없음. (K-시리즈 방침 표준 = [KLOTTO_CONNECT_HANDOFF.md](KLOTTO_CONNECT_HANDOFF.md) §9)
7. **스토어 설명을 방어적으로** — "행정안전부 안전신문고 신고 **작성 보조**, 제출은 사용자가 직접" 성격을 분명히. 특정인 표적이 아닌 공익 신고 보조임을 명시

## 6. 기술 설계 스케치

```
[블박 영상 파일 선택]  ← 사용자 (Photo Picker / 파일 선택, 권한 최소)
      ▼
[구간 탐색 + 프레임 추출]  MediaMetadataRetriever (Android 표준, 외부 의존 없음)
      ▼  사용자가 위반 순간 전/후 프레임 2~3장 지정
[번호판 영역 OCR]  ML Kit Text Recognition (온디바이스·한국어)
      ▼  인식 결과는 반드시 사용자 확인·수정 UI 경유 (오인식 전제)
[시각·장소 입력]  영상 Burn-in 시각을 사용자가 확인 입력 / 장소는 수동 또는 지도 선택
      ▼
[문안 생성]  로컬 템플릿 조립 (AI 없음, 조문 인용 없음)
      ▼
[결과]  캡처 이미지 2~3장 + 문안 텍스트 → 클립보드 복사 / 공유 시트
      ▼
[안전신문고 앱·웹으로 이동]  딥링크 또는 스토어 유도 → 사용자가 붙여넣고 본인인증·제출
```

### 재사용 가능한 K-시리즈 자산
| 필요 | 출처 |
|---|---|
| 다크골드 테마·스플래시·워터마크 | KDailyUtil / K_SERIES_ICON_RECIPE 규격 |
| Photo Picker(권한 불필요 이미지·미디어 선택) | KDailyUtil v1.1 정책 대응분 |
| OCR 결과 사용자 확인·수정 화면 패턴 | `KJangbu/app/.../feature/capture/ReceiptReviewScreen.kt` 등 3종 |
| 자매앱 상호연결(동적 레지스트리) | family.json에 한 줄 추가로 편입(§8, 재배포 불필요) |
| `openAppOrStore` (안전신문고 앱 이동) | KDailyUtil `core/util` 패턴 |

### 신규로 필요한 것
- ML Kit Text Recognition 의존성(온디바이스, K장부 ARCHITECTURE에서 이미 후보로 검토된 것)
- 영상 프레임 탐색·추출 UI (스크러버 + 프레임 미리보기)
- 번호판 후보 영역 크롭·확대 보조(인식률 개선용)
- 신고 문안 템플릿 + 신고 이력 로컬 저장

## 8. 권고 — 착수 순서

**앱을 만들기 전에 개인 로컬 도구로 두세 번 실제 사용해 볼 것.** 정책 문제가 아니라 **검증** 목적이다.

1. 실제로 얼마나 자주 신고하는가 (수요 검증)
2. **본인 블박 화질에서 번호판이 실제로 읽히는가** — 야간·역광·모션 블러에서 OCR이 무너지는 것이 이 기능의 **최대 기술 리스크**다. 여기서 안 읽히면 앱을 만들어도 못 쓴다
3. 문안 자동화가 체감 시간을 아끼는가 (안전신문고는 일시·장소·차량번호를 전부 수동 타이핑해야 하므로 절약 여지는 있음)

로컬 검증은 하루이틀이면 되고, **신규 앱 첫 심사가 오래 걸린다는 것은 K장부 v1.0.0으로 이미 실증됐다**. 가장 싼 검증을 먼저 한다. 검증 후 앱으로 올리면 자매앱 편입은 `family.json` 한 줄이다.
