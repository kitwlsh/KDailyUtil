# 🔁 매일 열게 만들기 — 리텐션 검토서

> 작성 2026-09-04. 질문: *「만들어두고 방치하면 덜 열게 된다. 비슷한 서비스도 많다. 보상(포인트·현금)은 아직 못 준다. 매일 한 번은 들어오게 할 방법이 없을까? 퀴즈 쪽에 뭘 해야 하나?」*

### 확정한 «되돌리기 어려운» 결정 2개

1. **출석 = 「오늘의 퀴즈를 끝까지 푼 것」**. 앱 실행은 출석이 아니다.

## 1. 진단 — 코드에서 확인한 사실

### 🔴 1-1. 모닝 브리핑 알람이 **일회성**이다 (매일 오지 않는다)

**「매일 아침 알림」이라고 만들어 놨는데, 실제로는 켠 다음날 한 번 울리고 영원히 끝난다.**

근거:
- [`BriefingScheduler.kt:15`](../app/src/main/java/com/kitwlshcom/kdailyutil/scheduler/BriefingScheduler.kt#L15) — `setExactAndAllowWhileIdle`은 **단발 알람**이다. 반복 알람이 아니다
- [`BriefingReceiver.kt:34`](../app/src/main/java/com/kitwlshcom/kdailyutil/receiver/BriefingReceiver.kt#L34) — 알람을 받으면 **알림만 띄우고 다음 알람을 다시 걸지 않는다**
- `scheduleBriefing()` 호출부는 **세 곳뿐**이고 전부 사용자 행동/부팅이다:
  - `BriefingViewModel.kt:173` 시간 변경 시 · `:182` 토글을 켤 때 · `BriefingReceiver.kt:71` **재부팅** 시

→ 즉 **사용자가 설정을 다시 만지거나 폰을 재부팅해야만** 알림이 되살아난다. 재부팅은 몇 주에 한 번이다.
→ **「자주 안 열게 된다」의 가장 큰 원인일 가능성이 높다.** 돌아올 유일한 초대장이 1일차 이후 발송되지 않는다.
→ 고치는 비용: **`showNotification()` 뒤에 다음 날짜로 재예약 한 줄.** 신규 기능 0개.

> ⚠️ 이건 «기능이 부족하다»가 아니라 «있다고 믿었던 기능이 없다»다. 개발자 기기에서는 설정을 자주 만져서 계속 되살아나기 때문에 **자기 폰으로는 영원히 안 보이는 종류의 실패**다 — 08-12 AI 모델 장애와 같은 유형이다.

### 🟡 1-2. 콘텐츠는 매일 들어오는데, 앱이 그 사실을 **알리지 않는다**

퀴즈 자동 생성 로봇은 **지금도 매일 정상 작동 중**이다(2026-09-04 실측):

| 항목 | 실측값 |
|---|---|
| GitHub Actions 최근 실행 | **09-03까지 매일 success**(08-26 1회만 failure) |
| 원격 문항 수(현재) | 우리말 114 · 트렌드 88 · 상식 207 · 여행 91 = **500문항** |
| 증가 속도 | 08-02에 346문항 → **한 달에 +154, 하루 약 5문제** |

**그런데 앱에는 「새 문제가 들어왔다」는 신호가 어디에도 없다.** 사용자는 어제와 오늘이 다르다는 것을 알 방법이 없다.
→ **이미 돈과 시간을 들여 만든 자산을 쓰지 않고 있다.** 매일 열 이유를 이미 생산하고 있으면서 배달을 안 한다.

### 🟡 1-3. 코드에 **'오늘'이라는 개념이 없다**

- 날짜를 다루는 파일은 `StockRepository`(장 날짜) **하나뿐**이다
- [`QuizStatsManager.kt`](../app/src/main/java/com/kitwlshcom/kdailyutil/data/QuizStatsManager.kt) 는 문제별 `attemptCount`/`correctCount`/`wrongCount`만 센다 — **언제 풀었는지 기록이 없다**
- `SettingsRepository`에 마지막 방문일·연속일수 같은 키가 없다

→ **출석·연속(스트릭)·「오늘의 성과」는 지금 당장은 만들 수 없다.** 날짜 기록을 넣는 것이 모든 리텐션 기능의 공통 1단계다.

### 🟡 1-4. 홈 화면에 앱의 흔적이 없다
Manifest에 **앱 위젯이 하나도 없다**. 사용자가 앱을 열겠다고 결심해야만 앱이 존재한다.

### ✅ 1-5. 이미 갖춰진 것 (새로 안 사도 되는 것)
- `POST_NOTIFICATIONS` · `SCHEDULE_EXACT_ALARM` · `RECEIVE_BOOT_COMPLETED` 권한 **전부 선언되어 있다**
- 알림 채널·PendingIntent·부팅 재등록 **코드가 이미 있다**(고쳐 쓰면 된다)
- **`androidx.work.runtime.ktx`가 의존성에 있는데 코드에서 한 번도 안 쓴다** → 일간 작업 스케줄러를 **새 라이브러리 없이** 붙일 수 있다
- 원격 콘텐츠 배달망 2개(`korean_quiz_data`, `k-series-config/family.json`) — **앱 재배포 없이** 매일 다른 것을 내려보낼 수 있다

## 2. 보상 없이 쓸 수 있는 레버 — 다방면 검토

> 전제: 포인트·현금성 보상은 **의도적으로 배제**한다. 비용·세금·정책(Play 결제/광고 정책) 문제가 생기고, 무엇보다 **보상으로 온 사용자는 보상이 끊기면 전부 나간다.** 아래는 전부 «보상 없이 작동하는 것»만 모았다.

| # | 레버 | 효과 | 비용 | 위험 |
|---|---|---|---|---|
| **A** | **브리핑 알람 매일 재예약** (§1-1 수정) | 🟢 매우 큼 | 🟢 몇 줄 | 🟢 없음 |
| **B** | **알림 문구를 매일 다르게** (오늘 헤드라인/새 문제 수/관심종목) | 🟢 큼 | 🟢 작음 | 🟡 실패 시 빈 문구 |
| **C** | **오늘의 퀴즈(데일리 세트)** | 🟢 큼 | 🟡 중간 | 🟢 낮음 |
| **D** | **출석·연속일수(스트릭)** | 🟢 큼 | 🟡 중간 | 🔴 끊기면 역효과 |
| **E** | **오답 노트 / 복습** | 🟡 중간 | 🟢 작음(데이터 이미 있음) | 🟢 없음 |
| **F** | **홈 화면 위젯** | 🟡 중간~큼 | 🔴 큼 | 🟡 신규 의존성 |
| **G** | **기록·배지**(최고 연속·누적 문항·정답률 추이) | 🟡 중간 | 🟢 작음 | 🟢 없음 |
| **H** | **자매앱 교차 유입**(K장부는 매일 여는 앱이다) | 🟡 중간 | 🟢 작음(레지스트리 있음) | 🟡 과하면 광고로 느껴짐 |

### A. 알람을 매일 다시 건다 — **제일 먼저, 제일 싸게**
`showNotification()` 직후 `BriefingScheduler.scheduleBriefing(hour, minute)`을 다시 호출한다. 이미 «지난 시각이면 내일로» 로직이 스케줄러에 있어서(`BriefingScheduler.kt:35`) **그대로 부르면 자동으로 내일이 잡힌다.**
- 함께 볼 것: `canScheduleExactAlarms()`가 false면 조용히 부정확 알람으로 떨어진다(`:47`) — 사용자에게 **한 번은 안내**해야 정시에 온다

### B. 알림에 '오늘 뭐가 새로운지'를 담는다
지금 문구는 **고정**이다 — 「모닝 브리핑 준비 완료! 📢」(`BriefingReceiver.kt:118`). 같은 문구를 사흘 보면 사람은 알림을 끈다. **알림을 끄면 리텐션 회복 수단이 영구히 사라진다** — 가장 비싼 실패다.
- 바꿀 것: *「오늘 새 문제 5개 · 관심종목 삼성전자 +2.1%」* 처럼 **매일 실제로 달라지는 한 줄**
- 원칙: **알림은 하루 1회.** 두 번째 알림부터는 이득보다 차단 위험이 크다

### C. 오늘의 퀴즈 — 퀴즈 쪽 답은 이것이다
지금 퀴즈는 **매번 500문항에서 랜덤 10개**다(`QuizRepository.kt:229` `.shuffled()` → `QuizViewModel.kt:163` `take(10)`). 잘 도는데, **끝이 없다.** 끝이 없으면 «오늘 몫을 다 했다»는 완결감이 없고, 완결감이 없으면 내일 다시 올 이유도 없다.

> **무한 랜덤은 «언제 해도 되니까 안 하게» 만든다. 하루치로 잘라야 오늘 하게 된다.**

- **날짜를 시드로** 문제를 뽑는다 → 그날은 누구에게나 같은 문제, 하루가 지나면 새 문제
- **5문제**(10개는 아침에 부담) · 다 풀면 **「오늘 완료 ✅」**
- 다 푼 뒤에 «더 풀기»로 기존 랜덤 모드를 열어 준다 — 하고 싶은 사람은 막지 않는다
- 새로 들어온 문제(하루 ~5개)를 **오늘의 세트에 우선 편성**하면 §1-2의 자산이 그대로 살아난다

### D. 출석·연속일수 — 보상 없이 작동하는 유일한 강한 장치
보상이 없어도 사람은 **쌓아 놓은 연속을 깨기 싫어한다**(손실 회피). 듀오링고가 무료로 이걸 한다.
- 필요: 날짜 기록(§1-3) — `SettingsRepository`에 `last_visit_date` / `streak_count` / `best_streak` 3개면 시작된다
- 🔴 **주의: 스트릭은 양날이다.** 한 번 끊기면 «어차피 망했다»며 아예 이탈한다
  - 완화책: **주 5일 달성** 같은 관대한 규칙, 또는 **하루 유예(streak freeze)** 를 기본 제공
  - 절대 하지 말 것: 끊긴 걸 알리는 알림(«연속이 끊겼어요!») — 죄책감 알림은 앱 삭제로 직행한다

### E. 오답 노트 — 데이터는 이미 다 쌓여 있다
`QuizStatsManager`가 문제별 오답 횟수를 **이미 저장하고 있는데 그걸 보여주는 화면이 없다.** 「내가 틀린 것만 다시」는 **개인화된 돌아올 이유**이고, 남이 못 베끼는 자산이다(§비슷한 서비스 많다는 문제의 답이기도 하다).
- 여기에 **날짜만 추가**하면(§1-3) 「3일 전에 틀린 문제 복습」 같은 간격 반복까지 열린다

### F. 위젯 — 효과는 크지만 지금은 아니다
홈 화면에 「오늘의 문제 1개」 또는 관심종목이 떠 있으면 **앱을 안 열어도 매일 눈에 띄고**, 탭하면 들어온다. 다만 Glance 신규 의존성 + 별도 레이아웃·업데이트 주기 설계가 필요하다 → **A~E가 자리 잡은 뒤**로 미룬다.

### G. 보상 대신 '기록'
돈이 안 드는 보상은 **자기 기록**이다. 최고 연속일수, 누적 학습 문항, 카테고리별 정답률 추이. 특히 **정답률이 오르는 그래프**는 그 자체가 계속할 이유가 된다.

### H. 자매앱 교차 유입
**K장부(가계부)는 원래 매일 여는 종류의 앱**이다. `family.json` 레지스트리가 이미 3앱을 연결하고 있으니, 한쪽에서 다른 쪽의 «오늘 할 일»을 가볍게 노출할 수 있다. 단 **과하면 광고로 읽힌다** — 하루 1회, 눈에 띄지 않는 자리에.

애널리틱스가 없다. 그래서 현재 이 판단은 **체감**이고, 개선해도 **효과를 알 수 없다.**
- 🟢 비용 0인 방법: **Play Console의 설치·제거·활성 기기 추이**를 vc8 배포 전후로 기록해 둔다
- 🟢 인앱 로컬 통계(사용자 기기 안에만 저장, 전송 없음)로 **최고 연속·평균 방문 간격**을 사용자 본인에게 보여준다 → 방침·양식 변경 불필요
- 🔴 외부 전송 애널리틱스는 정책 작업을 부른다 → §3

## 5. 권고 순서

| 단계 | 내용 | 근거 |
|---|---|---|
| **vc8** | 503 수정 + **A·B·날짜기록·C·D·E·G 전부** | ✅ **2026-09-04 구현 완료.** 사용자 결정으로 나누지 않았다. 새 권한 0개·전송 데이터 0개라 정책 작업이 없어 심사 위험이 낮다는 점이 근거 |

> 💡 **차별화 관점**: 비슷한 서비스가 많다는 것은 사실이다. 그러나 경쟁 상대는 「뉴스 앱」이나 「퀴즈 앱」 하나하나이고, **이 앱의 자산은 «뉴스+증시+학습+오디오가 한 곳에 있고, 매일 콘텐츠가 자동 생산된다»** 는 점이다. 매일 열 이유는 «유틸리티가 많아서»가 아니라 **«오늘치 콘텐츠가 있어서»** 여야 한다 — 그래서 §C(오늘의 퀴즈)가 퀴즈 쪽 답이다.

## 6. 착수 전 확인할 것

- [ ] §1-1 수정은 **실제 기기에서 이틀 연속** 알림이 오는지 확인해야 한다(하루만 보면 못 잡는다). 기기 시간을 앞당기는 방법으로 단축 검증 가능
- [ ] 알림 문구 변경(B)은 **네트워크 실패 시 폴백 문구**가 필요하다 — 빈 알림은 안 보내느니만 못하다
- [ ] 「오늘의 퀴즈」 날짜 기준은 **기기 로컬 시간**으로 한다(서버 없음). 자정 경계에서 세트가 바뀌는 것을 사용자가 이해할 수 있게 표기
- [ ] 스트릭 규칙(엄격 vs 관대)은 **되돌리기 어렵다** — 출시 전에 정한다. 권고 = **관대**(하루 유예 기본)
