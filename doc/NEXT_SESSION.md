## ✅ 할 일 1 — 503(모델 과부하) 대응 이식 — **코드 수정 완료(2026-08-25, `3f90470`) · 푸시 완료(09-04) · vc8 빌드 대기**

### 쉽게 말하면
**구글 AI 서버가 붐비면(503) KDailyUtil은 「연결에 실패했습니다」만 뱉고 끝났다.** 재시도도, 다른 모델로 넘어가지도 않았다. 사용자 눈에는 *「엄청 오래 걸리다가 그냥 실패」* 로 보이고, 원인을 알 방법이 없었다.

> ✅ **2026-08-25에 고쳤다.** 아래는 무엇을 왜 고쳤는지의 기록이다. **단 스토어(vc7)에는 아직 없다 — 반영하려면 vc8 빌드·업로드가 필요하다.**

**이건 추측이 아니다.** K장부가 08-18에 **실사용 신고 → 실제 API로 재현 → 원인 확정**까지 끝냈다(커밋 `d56ff6b`). 같은 날 실측:

| 모델 | 결과 |
|---|---|
| `gemini-flash-latest` | 🔴 **503 UNAVAILABLE**(응답까지 3~70초) |
| `gemini-3.5-flash` | ✅ 18.3초 정상 |
| `gemini-3.6-flash` | ✅ 44.9초 정상 |
| `gemini-2.5-flash` | ❌ 404(신규 계정 차단 — 08-12에 고친 그 장애) |
| `gemini-2.0-flash` | ❌ **이 계정에 아예 없다**(models 목록에 없음) |

### KDailyUtil에서 확인된 것 → 전부 조치함 (2026-08-25)

[`GeminiManager.kt`](../app/src/main/java/com/kitwlshcom/kdailyutil/data/remote/GeminiManager.kt) 기준:

1. 🔴 **503이 어느 그물에도 안 걸렸다** — `isModelUnavailable()`이 404 계열만 잡아서 503은 `throw e`로 빠졌다(폴백도 재시도도 없음). `testConnection()`의 오류 분기에도 503 칸이 없어 **영문 원문이 그대로 노출**됐다.
2. 🔴 **폴백 후보에 없는 모델이 들어 있었다** — `FALLBACK_MODELS`의 마지막 칸이 `gemini-2.0-flash`였다. **이 계정에 존재하지 않는 모델**이라 폴백 한 칸이 헛돌았다.
3. 🟡 **`lastGoodModel`이 없었다** — 인스턴스 단위 `resolved`만 있어서, 기본 모델이 503으로 막힌 동안 **호출마다 그 모델을 먼저 다시 찔렀다**(503 응답까지 3~70초). 「너무 오래 걸린다」의 절반이 이것이었다.

### 실제로 한 것 (커밋 `3f90470`)
원본: `KJangbu` 저장소 커밋 `d56ff6b` (파일 3개 · 81줄). 배경·실측은 커밋 메시지와 `KJangbu/doc/OPERATIONS.md`.

- `isOverloaded()` 추가 → **503은 «다음 모델로 넘어간다»**
  - ⚠️ **429와 다르게 다뤄야 한다.** 429는 기다리면 풀리지만 **503은 그 모델 자체가 붐비는 것이라 기다려도 안 풀린다** → 폴백이 맞는 대응이다
- 오류 문구에 503 분기 → *「AI 서버가 붐빈다, 당신 사용량 문제가 아니다」*  
  - 🔴 한도 소진으로 읽히면 사용자가 «내가 많이 썼나» 하고 그냥 기다린다
- **실패 원문을 `Log.w`로 남긴다** — 번역해서 보여주는 것과 별개다. 로그에 없으면 원인 미상 오류는 영영 조사할 수 없다(이번이 그 사례다)
- `FALLBACK_MODELS`에서 `gemini-2.0-flash` 제거 → `gemini-3.6-flash`로 교체
- `lastGoodModel`(앱 전역) 도입

**추가로 한 것 — 오류 안내를 한 곳(`aiErrorMessage`)으로 모았다.**
화면마다 `${e.message}`를 그대로 붙이고 있어서 **같은 사고를 화면 수만큼 다시 겪는** 구조였다. 사용자에게 AI 오류를 보여주는 **14곳 전부**를 이 함수로 보냈다. `StockViewModel`의 429 판정도 통일했다(`RESOURCE_EXHAUSTED`를 놓치고 있었다).

**회귀 테스트 19건 신설** — ✅ `:app:testDebugUnitTest` **20건 전부 통과** · `:app:compileReleaseKotlin` 성공.
- `AiErrorMessageTest`(10건) — 문구가 아니라 **«어느 문제인지 구분하는가»** 를 고정(503↔429↔404↔키, 404 문구가 503 판정에 안 걸리는지, 폴백 후보에 없는 모델이 없는지)
- `GeminiFallbackTest`(9건) — **폴백 루프 실동작**. 503→다음 후보 / 404→다음 후보 / **429·키오류는 넘어가지 않음** / 전부 막히면 마지막 사유 / `lastGoodModel`이 다음 인스턴스에 전달 / 원격 레버 우선순위
  - 이를 위해 `askWithFallback(call)`로 **호출부를 주입 가능하게** 뺐다(기기·네트워크·키 없이 검증). `build.gradle.kts`에 `unitTests.isReturnDefaultValues = true`도 필요했다(`android.util.Log`가 «not mocked»로 던진다 — K장부가 이미 푼 함정)

> 🔬 **뮤테이션 시험으로 테스트가 진짜인지 확인했다** — `!isOverloaded(e)` 조건을 수정 전으로 되돌리자 **`GeminiFallbackTest` 4건이 정확히 실패**했고, 되돌리니 전부 통과했다. 통과만 하고 아무것도 못 잡는 테스트가 아니다.

> 🟢 **덤으로 §할 일 3의 준비가 끝났다** — KDailyUtil에 없던 **단위 테스트 기반이 생겼다**(`ExampleUnitTest` 하나뿐이었다). `aiModel` 회귀 테스트 이식은 이제 파일 하나 추가하면 된다.

## 🟢 할 일 4 — AI 체험판 (선택 · 다음 «기능» 후보 1순위)

### 쉽게 말하면
**키를 발급받지 않은 사람도 AI를 몇 번은 그냥 써볼 수 있게 하는 기능.** 지금 KDailyUtil은 키가 없으면 AI를 아예 못 쓴다.

K장부에는 **이미 만들어져 돌아가고 있다**(체험 20회 + 킬스위치). 설계 근거·약관 검토·광고/구독을 왜 안 하기로 했는지까지 정리돼 있다 → **`KJangbu/doc/AI_KEY_POLICY.md`** (정책의 단일 기준. KDailyUtil에도 그대로 적용된다)

### ⚠️ 그대로 복사하면 안 되는 이유 3가지
1. **횟수가 안 맞는다** — K장부는 AI 쓰는 곳이 사실상 영수증 인식 하나라 20회면 충분하다. KDailyUtil은 **13가지**라 한 번씩만 눌러봐도 절반이 사라진다 → **분야별 배분**(뉴스/배움터/증시). 제안: 7 / 7 / 6
2. **세는 단위** — '호출'이 아니라 '**사용자가 한 작업**' 단위. 실패는 차감하지 않는다
3. **작업 순서를 반드시 지킬 것** — `키 읽는 곳을 한 군데로 모으기 → 카운터 → 안내 → 원격 중단 스위치 → **개발자 키 넣기는 맨 마지막**`. 순서를 어겨 키부터 넣으면 **카운터 없이 전 기능이 무제한**으로 돌아간다

> KDailyUtil은 키를 읽는 코드가 **15곳에 흩어져** 있다. 한 곳으로 모으는 작업이 먼저다.
> 💡 **08-25에 오류 안내(`aiErrorMessage`)를 한 곳으로 모으는 것은 이미 했다.** 남은 건 **키를 읽는 15곳**이고, 그것이 체험판의 1단계다.

3. 다시 위로 올라가 **[연결 테스트]** 버튼을 누른다
4. **`✅ 연결 성공! (모델 gemini-3.5-flash)`** 라고 뜨면 **레버가 살아 있는 것이다.** 확인 끝.
   - 다른 모델 이름이 뜨면 → 2번 새로고침을 안 눌렀거나, family.json 저장이 안 된 것

### B-3. 반드시 되돌린다 🔴

1. `family.json`에서 방금 넣은 `"aiModel": ...` **줄을 지우고** 저장
2. 앱에서 다시 **자매앱 새로고침(↻)**
3. 🔴 **그리고 앱을 완전히 종료했다가 다시 켠다** — 최근 앱 목록에서 밀어 없애거나, `설정 > 앱 > KDailyUtil > 강제 중지`

> ❗ **왜 강제 종료까지 해야 하나 (함정)**: 코드가 «값이 없으면 아무것도 건드리지 않는다»로 되어 있다
> (`FamilyRepository.applyAiModel`: `if (raw.isEmpty()) return`). 원격이 앱을 망가뜨리지 못하게 한 안전장치인데,
> 그 대가로 **줄을 지워도 이미 켜져 있는 앱의 메모리에는 그 모델이 그대로 남는다.** 껐다 켜야 원래대로 돌아온다.

> ⚠️ **이 레버는 K장부도 같이 읽는다.** 되돌린 뒤 K장부도 한 번 껐다 켜 줄 것.

## C. 앱 기능 — 기기 날짜를 바꿔 가며 (10분)

**준비**: `설정 > 시스템 > 날짜 및 시간`에서 **「자동 날짜 및 시간」을 끈다**(수동 변경을 하려면 꺼야 한다).
확인이 끝나면 **반드시 다시 켠다.**

### C-1. 오늘의 퀴즈 · 출석

| 순서 | 할 일 | 성공 판정 |
|---|---|---|
| 1 | 배움터 탭 → **「오늘의 5문제 풀기」** | 문제가 5개 나오고 끝나면 결과 화면 |
| 2 | 결과 화면 확인 | 위에 **🔥「오늘의 퀴즈 완료 · 1일 연속」** 배너 |
| 3 | 배움터 첫 화면으로 | 카드가 초록색 **「오늘 완료!」** 로 바뀜 |
| 4 | **「내 기록」** 탭 | 현재 연속 **1일**, 누적 5문항, 배지 「첫걸음」 획득 |

### C-2. 연속(스트릭)이 이어지는지 — 날짜를 하루 넘긴다

1. 기기 날짜를 **내일**로 바꾼다 → 앱을 껐다 켠다
2. 배움터 → 카드가 다시 **「오늘의 퀴즈」**(미완료)로 돌아와 있어야 한다
3. 🔴 **문제가 어제와 다른 5문제여야 한다** ← 「오늘의 퀴즈」가 제대로 도는지 보는 핵심
4. 풀고 나면 **「2일 연속」**

### C-3. 하루 빠져도 살아나는지 (유예)

1. 기기 날짜를 **모레**(하루 건너뛰기)로 바꾼다 → 앱 재시작
2. 오늘의 퀴즈를 푼다
3. **「3일 연속」** 으로 이어지면 성공 (끊겨서 1일로 돌아가면 유예가 안 먹은 것)

### C-4. 오답 노트

1. 퀴즈를 풀면서 **일부러 몇 개 틀린다**
2. 배움터 첫 화면 → **「오답 노트」** 타일에 **「복습할 N개」** 로 개수가 뜬다
3. 눌러서 들어가면 **틀렸던 그 문제들**이 나온다

### C-5. 🔴 알람이 «이틀» 오는지 — 이번에 고친 그 버그

**하루만 보면 못 잡는다.** 예전 버그가 «첫날은 오고 둘째 날부터 안 오는» 것이었기 때문이다.

1. 설정 탭 → **「자동 브리핑 사용」** 을 켠다
2. **「브리핑 시간」** 을 **지금부터 3~5분 뒤**로 맞춘다 (예: 지금이 14:20이면 14:25)
   - ⚠️ 1~2분 뒤로 맞추면 «너무 가깝다»고 판단해 내일로 넘어간다(5초 가드)
3. 앱을 홈 버튼으로 내려놓고 기다린다 → **알림이 오면 1일차 성공** ✅
4. **여기서부터가 진짜다.** 기기 날짜를 **내일**로 바꾸고, 시각을 **알람 시각 2~3분 전**으로 맞춘다
   (예: 브리핑 시간이 14:25면 → 날짜 +1일, 시각 14:22)
5. 기다린다 → **알림이 또 오면 성공** ✅✅
   - 여기서 안 오면 이번 수정이 안 먹은 것이다 (예전 동작과 같음)
6. 여유가 되면 4~5를 한 번 더 반복해 3일차까지 본다

**알림 문구도 같이 본다**: 「모닝 브리핑 준비 완료!」 아래에
**「새 문제 N개 · N일 연속 도전 중 — 오늘의 뉴스와 퀴즈가 기다립니다」** 처럼
**매일 달라지는 한 줄**이 붙어 있으면 그 부분도 정상이다.

### C-6. 정리

- 기기 **「자동 날짜 및 시간」을 다시 켠다**
- 날짜를 앞뒤로 움직였으므로 **연속 기록이 실제와 다르게 남아 있을 수 있다.** 시험용이니 신경 쓰지 않아도 되지만,
  깨끗하게 하고 싶으면 `설정 > 앱 > KDailyUtil > 저장공간 > 데이터 삭제`(주의: API 키·관심종목 등 모든 설정이 지워진다)

## D. 참고 — 나중에 문제가 생겼을 때 당길 레버 2개

| 상황 | 레버 | 방법 |
|---|---|---|
| **앱의 AI가 전부 실패** | `aiModel` | `k-series-config/family.json` 최상위에 `"aiModel": "<모델명>"` 추가 → 앱에서 자매앱 새로고침. **K장부도 같이 바뀐다** |
| **퀴즈 로봇이 모델 때문에 실패** | `QUIZ_MODEL` | `korean_quiz_data` 저장소 → Settings → Secrets and variables → Actions → **Variables** 탭 → `QUIZ_MODEL` 에 모델명 입력 → Actions에서 수동 실행 |

둘 다 **앱을 새로 내지 않고** 고치는 수단이다. 문제가 풀리면 값을 지워 원상복구한다.
