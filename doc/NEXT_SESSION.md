## 🔴 할 일 1 — KDailyUtil v1.7 배포 **(급함)**

### 쉽게 말하면
**지금 스토어에서 KDailyUtil을 새로 받은 사람은 AI 기능이 하나도 안 된다.**

### 왜 이런 일이
앱 안에 AI 모델 이름을 `gemini-2.5-flash`라고 **특정 버전으로 박아**뒀는데, 구글이 그 모델을 **신규 사용자에게만 차단**했다. 예전부터 쓰던 계정은 그대로 되기 때문에, 개발자 기기에서는 멀쩡해 보여서 몰랐다. K장부 작업 중 새 계정으로 시험해보다 발견했다.

영향받는 기능은 뉴스 AI 분석·대화, 책 페이지 글자 인식, AI 퀴즈, 증시 AI 리포트 등 **13가지**다.

### 지금 상태
**고치는 건 다 끝났다.** 모델 이름을 특정 버전 대신 '항상 최신' 별칭으로 바꾸고, 그것마저 막히면 다른 모델로 자동 전환하게 했고, 최악의 경우 **앱을 다시 배포하지 않고도 원격으로 모델을 바꿀 수 있게** 해뒀다. 실제 기기에서 동작 확인까지 마쳤다.

## ✅ 할 일 2 — 개인정보처리방침 배포본 교체 — **완료(2026-08-10)**

> `k-series-config` 커밋 `7c6abd4` 푸시 완료. 아래는 무엇을·왜 바꿨는지 기록으로 남긴 것이다.
> ⚠️ **남은 확인 1건**: Play Console **앱 콘텐츠 > 데이터 안전** 양식이 이 방침과 일치하는지 대조해야 한다(v1.7 업로드 시). 방침과 양식이 어긋나면 정책 위반이다 — 상세 = [`AI_KEY_NOTES.md`](AI_KEY_NOTES.md) §4-2b.

### 쉽게 말하면
**"AI에 보낸 내용이 어떻게 쓰이는지"를 방침에 정확히 적어야 한다.**

구글 약관을 확인해 보니, **무료 등급**에서는 사용자가 AI에 보낸 글·사진이 *구글 제품 개선에 사용될 수 있고, 품질 확인을 위해 사람이 읽을 수도 있다*. (유료 등급은 해당 없음.) 그런데 기존 방침에는 *"오직 해당 기능의 결과를 만드는 목적으로만 사용됩니다"* 라고 적혀 있어서 **사실과 달랐다.**

### 왜 지금
사용자가 직접 발급하는 키도 **대부분 무료 등급**이라, **지금 스토어에 있는 v1.6에도 이미 해당된다.** 그리고 방침은 웹페이지라서 **앱 배포와 상관없이 지금 바꾸면 즉시 반영**된다. → **v1.7보다 먼저 해도 되고, 그게 낫다.**

### 어떻게 했나 (다음에 방침 고칠 때 그대로 재사용)
KDailyUtil 저장소의 수정본을 호스팅 저장소에 복사해서 커밋·푸시하면 끝이다.
단, **`cp`를 그냥 쓰면 안 된다** — 호스팅 레포의 방침 3종은 **CRLF**, KDailyUtil 원본은 **LF**라서
그대로 복사하면 **파일 전체가 diff로 잡혀 실제 변경을 검토할 수 없다.** 변환해서 복사한다.

```bash
cd d:/DATA/20_Source/80_Git_HUB/k-series-config/k-series-config
sed 's/$/\r/' d:/DATA/20_Source/80_Git_HUB/KDailyUtil/KDailyUtil/doc/privacy-kdailyutil.html \
  > privacy-kdailyutil.html
git diff --stat          # ← 몇 줄만 바뀌어야 정상 (이번엔 5+/4-)
git add privacy-kdailyutil.html && git commit -m "docs: …" && git push
```

확인: <https://kitwlsh.github.io/k-series-config/privacy-kdailyutil.html> (제8조)

> 앱 안에는 이미 같은 고지가 들어가 있다(v1.7부터 보임).

## 🟢 할 일 3 — AI 체험판 (선택 · 급하지 않음)

### 쉽게 말하면
**키를 발급받지 않은 사람도 AI를 몇 번은 그냥 써볼 수 있게 하는 기능.** 지금 KDailyUtil은 키가 없으면 AI를 아예 못 쓴다(안내만 뜬다).

K장부에는 **이미 만들어져 돌아가고 있다**(체험 20회 + 문제 생기면 원격으로 즉시 중단하는 스위치). 설계 근거·약관 검토·광고/구독을 왜 안 하기로 했는지까지 전부 정리돼 있다 → **`KJangbu/doc/AI_KEY_POLICY.md`** (정책의 단일 기준. KDailyUtil에도 그대로 적용된다)

### ⚠️ 그대로 복사하면 안 되는 이유 3가지
1. **횟수가 안 맞는다** — K장부는 AI 쓰는 곳이 사실상 영수증 인식 하나라 20회면 충분하다. KDailyUtil은 **13가지**라서 한 번씩만 눌러봐도 절반이 사라진다. → 총량 말고 **분야별 배분**(뉴스/배움터/증시)을 검토할 것. 제안: 7 / 7 / 6
2. **세는 단위** — '호출'이 아니라 '**사용자가 한 작업**' 단위로 센다. 실패는 차감하지 않는다
3. **작업 순서를 반드시 지킬 것** — `키 읽는 곳을 한 군데로 모으기 → 카운터 → 안내 → 원격 중단 스위치 → **개발자 키 넣기는 맨 마지막**`. 순서를 어겨 키부터 넣으면 **카운터 없이 전 기능이 무제한으로 돌아간다**

> KDailyUtil은 키를 읽는 코드가 **15곳에 흩어져** 있다. 한 곳으로 모으는 작업이 먼저다.
> 현재 KDailyUtil에는 개발자 키를 넣을 배선 자체가 **없다** — 넣을 자리가 없는 게 정상 상태다.
